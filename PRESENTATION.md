# Ten-minute prototype presentation

Run all smoke checks and prepare saved cases BEFORE presenting. Keep the app,
one screening PDF, workflow figure and Simulink model ready in separate tabs.

| Time | Show | Say |
|---|---|---|

| 1:00–2:00 | Your architecture | Quality gate protects downstream analysis; original images and every decision remain auditable. |

## Opening

“Our prototype brings automated retinal screening into a review workflow. It
checks whether an image is suitable for analysis, retains the original, shows
retinal evidence and the classifier's attention, and creates an annotated
report for an ophthalmologist. We also model the equipment and review capacity
needed for a district program.”

## What is implemented versus provisional

Implemented: working image ingestion/QA/enhancement; morphological/Hessian
retinal and lesion candidate overlays; integration of the existing trained
MATLAB classifier; genuine Grad-CAM when supported; optional trained feature
branch/fusion; calibration and test scripts; doctor review recording; actual
PDF output; Poisson/fluid MATLAB simulation and generated Simulink queue model.

Provisional: quality thresholds, candidate accuracy, disc/fovea estimates,
domain transfer from APTOS to IDRiD, fusion weights, clinical usefulness,
referral threshold and resource assumptions. No subpixel MA or NV detector
claim. No >90% sensitivity/>85% specificity claim without measured test results.

## Likely questions

**Did you achieve the required accuracy?**
“Here are the metrics we actually measured, including how many images were
withheld. If a target is not met, this is a baseline prototype and the target
remains a validation requirement.” If you did not run validation, say so.

**Why are some IDRiD images held for review?**
“Quality criteria are provisional and depend on capture conditions. A borderline
focus score causes review rather than an automatic diagnosis. We need reviewer
labels to tune these thresholds.”

**Is Grad-CAM a lesion detector?**
“No. It shows CNN attention for a class. Our separate lesion overlays are
untrained candidate detectors, so both explanations need clinical assessment.”

**Does the report prescribe treatment?**
“No. It documents model/evidence outputs and reviewer-entered findings. The
doctor makes the diagnosis and treatment decision.”

**How did you handle the unknown preprocessing?**
“We documented two full-frame pixel-scaling adapters and compared them on a
development subset. This selects an empirical demo adapter; the original
training code is still needed to verify exact preprocessing.”

**Is the resource allocation optimal?**
“We size independent bottleneck capacities with utilization headroom and compare
queue traces under stated assumptions. Cost optimization and patient-level
discrete-event service distributions are future extensions.”

## Backup procedure

If live processing stalls, show the saved original/overlay/Grad-CAM PNGs and the
actual generated PDF. Explain that these were generated by the prototype
before the presentation. Use the saved workflow plot and open `.slx` model.
Never pass a saved output off as a newly completed live result.
